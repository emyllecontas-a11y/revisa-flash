B) COMO FICOU O RESET DO ERRO NO STUDYCARD
============================================================

Abordagem usada: `useEffect` com a URL como dependência.

```tsx
// Resetar estado de erro quando a URL da imagem muda (ex.: troca de card)
useEffect(() => {
  setFrontImageError(false);
}, [frontImageUrl]);

useEffect(() => {
  setBackImageError(false);
}, [backImageUrl]);
```

Por que não usei `key` no StudyCard (em flashcards.tsx ~linha 959):
- O StudyCard já recebe `frontImageUrl` e `backImageUrl` como props
- O `key` no componente pai faria o React remover e recriar o componente inteiro (perdendo estado de `flipped`, animação de virar, etc.)
- `useEffect` com a URL como dependência é mais cirúrgico: só zera o flag de erro, mantém todo o resto
- Funciona tanto para troca de card quanto para edição da imagem no mesmo card

C) ORDEM FINAL DO HANDLEEDITCARD
============================================================

ORDEM ANTIGA (problemática):
  1. Deletar imagem antiga do Storage
  2. Upload nova imagem
  3. Chamar editCard
  → Risco: se editCard falhar, imagem antiga já foi apagada e nova pode ter ficado órfã

ORDEM NOVA (segura):
  PASSO 1 — Upload das novas imagens (se houver arquivo novo)
    - frontImageFile → compressAndUploadImage → frontImageUrl = uploadedUrl
    - backImageFile → compressAndUploadImage → backImageUrl = uploadedUrl
    - Guarda as URLs em `uploadedFrontUrl` / `uploadedBackUrl` para limpeza se falhar

  PASSO 2 — Preparar remoção (NÃO apaga ainda, só guarda URLs)
    - Se usuário marcou "remover": frontImageUrl = null, oldFrontImageUrl = URL antiga
    - Se usuário substituiu (enviou nova): oldFrontImageUrl = URL antiga

  PASSO 3 — Chamar editCard e AGUARDAR SUCESSO
    - await editCard(..., frontImageUrl, backImageUrl)

  PASSO 4 — SÓ AGORA apagar imagens antigas do Storage (pós-sucesso)
    - Para cada oldFrontImageUrl / oldBackImageUrl:
      * Extrai path da URL
      * Verifica se path.startsWith(`${userId}/`) → ownership check
      * Se sim: deleteFlashcardImage() — se falhar, apenas console.warn

  TRATAMENTO DE ERRO (catch):
    - Se editCard falhou APÓS upload de novas imagens:
      * Apaga uploadedFrontUrl e uploadedBackUrl (órfãs)
      * Mantém imagens antigas intactas no Storage
      * Mostra toast.error + setErrorMessage
