## 1. CÓDIGO REAL — ContentTreeSelector.tsx (busca de dados)

```typescript
// Linhas 1-5: imports
import { getDisciplines, getTopics } from "@/lib/supabaseClient";

// Linhas 36-75: loadData (useCallback com dependência [userId])
const loadData = useCallback(async () => {
  if (!userId) return;

  setLoading(true);
  setError(null);

  try {
    // Buscar disciplinas
    const discResult = await getDisciplines(userId);        // <-- USA getDisciplines DO SUPABASE CLIENT
    if (!discResult.success) throw new Error(discResult.error || "Erro ao buscar disciplinas");

    const disciplinesData = discResult.data || [];
    setDisciplines(disciplinesData);

    // Buscar tópicos para cada disciplina em paralelo
    const topicsPromises = disciplinesData.map(async (disc) => {
      const topicResult = await getTopics(disc.id);         // <-- USA getTopics DO SUPABASE CLIENT
      if (topicResult.success && topicResult.data) {
        return { disciplineId: disc.id, topics: topicResult.data };
      }
      return { disciplineId: disc.id, topics: [] };
    });

    const topicsResults = await Promise.all(topicsPromises);
    const topicsMap: Record<string, Array<{ id: string; name: string }>> = {};
    topicsResults.forEach(({ disciplineId, topics }) => {
      topicsMap[disciplineId] = topics.map((t: any) => ({ id: t.id, name: t.name }));
    });
    setTopicsByDiscipline(topicsMap);

    // Expandir primeiras disciplinas por padrão
    if (disciplinesData.length > 0) {
      const initialExpanded = new Set(disciplinesData.slice(0, 3).map((d) => d.id));
      setExpandedDisciplines(initialExpanded);
    }
  } catch (err) {
    console.error("Erro ao carregar árvore de conteúdo:", err);
    setError(err instanceof Error ? err.message : "Erro ao carregar disciplinas e tópicos");
  } finally {
    setLoading(false);
  }
}, [userId]);

// Linha 77: useEffect dispara loadData
useEffect(() => {
  loadData();
}, [loadData]);
```

## 3. CÓDIGO REAL — supabaseClient.ts (getDisciplines / getTopics ATUAIS)

```typescript
// Linhas 175-193: getDisciplines
export const getDisciplines = async (userId: string) => {
  try {
    const { data, error } = await supabase   // <-- CLIENTE ANON (linha 13)
      .from('disciplines')
      .select('*')
      .eq('user_id', userId)
      .neq('isdeleted', true)                // <-- CORRETO (fix aplicado)
      .order('createdAt', { ascending: true }); // <-- CORRETO (fix aplicado)

    if (error) throw error;
    return { success: true, data };
  } catch (error: any) {
    console.error('Erro ao buscar disciplinas:', error);
    return { success: false, error: error.message };
  }
};

// Linhas 223-241: getTopics
export const getTopics = async (disciplineId: string) => {
  try {
    const { data, error } = await supabase   // <-- CLIENTE ANON
      .from('topics')
      .select('*')
      .eq('discipline_id', disciplineId)
      .neq('isdeleted', true)                // <-- CORRETO
      .order('createdAt', { ascending: true }); // <-- CORRETO

    if (error) throw error;
    return { success: true, data };
  } catch (error: any) {
    console.error('Erro ao buscar tópicos:', error);
    return { success: false, error: error.message };
  }
};
```

> **Observação crítica:** Ambas as funções usam `supabase` (constante exportada na linha 13), que é o **cliente ANON** criado sem autenticação:
> ```typescript
> export const supabase = createClient(supabaseUrl, supabaseAnonKey);
> ```
> As tabelas `disciplines` e `topics` têm **RLS habilitado** (políticas `user_id = auth.uid()`). O cliente ANON **não tem `auth.uid()`**, logo a query retorna **vazio** (sem erro, apenas 0 linhas) — comportamento esperado do Postgres RLS.

| Hipótese | Classificação | Evidência |
|----------|---------------|-----------|
| **H7. `getDisciplines`/`getTopics` usam cliente ANON (sem token) → RLS bloqueia → retorna array vazio sem erro** | **CONFIRMADA** | `supabaseClient.ts` linhas 13, 178, 226: `const supabase = createClient(...)` (ANON) usado em `getDisciplines`/`getTopics`; tabelas têm RLS `user_id = auth.uid()`; ANON key não tem `auth.uid()` |

> **Por que conteudo.tsx funciona:** Lê do **RxDB local** (offline-first), que já sincronizou os dados via `getSupabaseWithToken()` (autenticado) em background. O seletor **ignora o cache local** e vai direto ao Supabase com credenciais insuficientes.

## 7. CAUSA RAIZ (1 linha)

> **O ContentTreeSelector usa `getDisciplines`/`getTopics` do `supabaseClient.ts`, que executam queries no cliente ANON (sem token Clerk); as tabelas `disciplines`/`topics` têm RLS ativo exigindo `auth.uid()`, então a query retorna 0 linhas sem erro, disparando o empty state "Nenhuma disciplina cadastrada".**
