# RELATÓRIO DE CORREÇÃO: Filtro isdeleted NULL (Dados Legados)

## Resumo
Corrigido filtro `.eq('isdeleted', false)` → `.neq('isdeleted', true)` nas queries da hierarquia de conteúdo (disciplines, topics) para incluir registros legados com `isdeleted = NULL`.

**Causa raiz**: A coluna `isdeleted` (sem underscore) no Supabase tem registros legados com `NULL`. O filtro `.eq('isdeleted', false)` exclui `NULL` (pois `NULL != false` no SQL). A solução `.neq('isdeleted', true)` inclui tanto `false` quanto `NULL` (trata NULL como "não deletado").

---

## Colunas Reais no Supabase (Evidência)

| Tabela | Coluna no DB | Tipo | Observação |
|--------|--------------|------|------------|
| `disciplines` | `isdeleted` | boolean | Sem underscore, lowercase |
| `topics` | `isdeleted` | boolean | Sem underscore, lowercase |
| `subtopicos` | (RxDB local) | boolean | Usa `isDeleted` camelCase no RxDB; sincroniza via queue |

**Confirmação**: 
- `createDiscipline`/`createTopic` em `supabaseClient.ts` inserem `created_at`/`updated_at` mas **não** setam `isdeleted`
- Schemas RxDB em `db.ts`: `disciplines`/`topics` usam `isDeleted` (camelCase) localmente
- Queries diretas no Supabase usam `isdeleted` (lowercase)

## Arquivos Alterados

### 1. `src/lib/supabaseClient.ts`
**Funções**: `getDisciplines`, `getTopics`
- **Antes**: Sem filtro `isdeleted`
- **Depois**: Adicionado `.neq('isdeleted', true)` após filtro de usuário/disciplina
- **Diff**:
```diff
 export const getDisciplines = async (userId: string) => {
   try {
     const { data, error } = await supabase
       .from('disciplines')
       .select('*')
       .eq('user_id', userId)
+      .neq('isdeleted', true)
       .order('createdAt', { ascending: true });
```

```diff
 export const getTopics = async (disciplineId: string) => {
   try {
     const { data, error } = await supabase
       .from('topics')
       .select('*')
       .eq('discipline_id', disciplineId)
+      .neq('isdeleted', true)
       .order('createdAt', { ascending: true });
```
