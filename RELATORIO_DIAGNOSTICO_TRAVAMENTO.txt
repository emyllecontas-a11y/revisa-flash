## 2. INSPEÇÃO DOS ARQUIVOS SUSPEITOS

### 2.1 WeeklyGridEditor.tsx — **CAUSA PROVÁVEL**
**Evidência:** `useCallback` com dependência `toast` que retorna objeto novo a cada render → loop infinito.

**Trechos relevantes (linhas 75-82, 240-250):**
```typescript
const toast = useToast();  // Retorna NOVO objeto a cada render

const loadBlocks = useCallback(async () => {
  // ... usa toast.error, toast.success
}, [userId, weekStart, toast]);  // ← toast muda a cada render!

useEffect(() => {
  loadBlocks();
}, [loadBlocks]);  // ← Dispara a cada render porque loadBlocks muda
```

**Por que trava:** `useToast()` cria wrapper functions novas a cada render. O `useCallback` recria `loadBlocks` a cada render. O `useEffect` roda a cada render. `loadBlocks` chama `setBlocks` → re-render → loop infinito → congela o browser.

## 5. CAUSA RAIZ MAIS PROVÁVEL (uma linha)

**`useToast()` em `src/hooks/useToast.ts` retorna um objeto literal novo a cada chamada, fazendo com que `useCallback` em `WeeklyGridEditor.loadBlocks` e `ExceptionsManager.loadData` sejam recriados a cada render, disparando `useEffect` em loop infinito que congela o browser.**

---

## 6. RECOMENDAÇÃO DE CORREÇÃO (sem código)

**Arquivo único a corrigir:** `src/hooks/useToast.ts`

**Ação:** Envolver o retorno de `useToast` em `useMemo` com array de dependências vazio `[]`, para que o objeto com as funções `success`, `error`, `info`, `warning`, `undoable` seja **estável** (mesma referência) entre renders.

**Por que funciona:** As funções wrapper apenas delegam para `sonner.toast` (já estável). Memoizar o objeto evita que consumidores (`useCallback` com `toast` nas deps) se recriem inutilmente.

**Impacto:** Corrige **ambos** componentes travados (`WeeklyGridEditor` e `ExceptionsManager`) com uma mudança de 1 linha no hook compartilhado. Zero risco de regressão em outros fluxos.

## 7. OBSERVAÇÃO ADICIONAL (não bloqueante)

Inconsistência de `Weekday` entre componentes:
- `types/study-plan.ts`: `Weekday = 0|1|2|3|4|5|6` com **0 = Domingo**
- `WeeklyGridEditor.tsx`: `WEEKDAY_NAMES = ["Seg","Ter","Qua","Qui","Sex","Sáb","Dom"]` → **índice 0 = Segunda** (usa `dayIdx as Weekday`)
- `ExceptionsManager.tsx`: `WEEKDAY_NAMES = ["Dom","Seg","Ter","Qua","Qui","Sex","Sáb"]` → **índice 0 = Domingo** (correto)

Isso causa desalinhamento de dados (blocos salvos com weekday errado), mas **não causa travamento**. Corrigir em fase posterior.
