## 2. CORREÇÃO A — TRAVAMENTO (crítica)

**Arquivo:** `src/hooks/useToast.ts`

**Problema:** `useToast()` retornava objeto novo a cada render. Componentes `WeeklyGridEditor.loadBlocks` e `ExceptionsManager.loadData` usavam `useCallback` com `toast` na dependência → recriados a cada render → `useEffect` dispara a cada render → `setState` → loop infinito → browser congela nas abas "Rotina semanal", "Exceções da semana" e ao clicar "Montar a minha semana".

**Solução:** Envolver o retorno do hook em `useMemo` com array de dependências vazio `[]`. As funções wrapper apenas delegam para `sonner.toast` (já estável). Memoizar o objeto evita que consumidores recriem inutilmente.

**Diff:**
```diff
// src/hooks/useToast.ts
import { useMemo } from "react";
import { toast } from "sonner";

interface ToastAction {
  label: string;
  onClick: () => void | Promise<void>;
}

interface ToastOptions {
  description?: string;
  duration?: number;
  action?: ToastAction;
}

export function useToast() {
  return useMemo(() => ({
    success: (msg: string, opts?: ToastOptions) => toast.success(msg, opts),
    error: (msg: string, opts?: ToastOptions) => toast.error(msg, opts),
    info: (msg: string, opts?: ToastOptions) => toast.info(msg, opts),
    warning: (msg: string, opts?: ToastOptions) => toast.warning(msg, opts),

    undoable: (
      msg: string,
      onUndo: () => void | Promise<void>,
      opts?: { description?: string; duration?: number; undoLabel?: string }
    ) =>
      toast(msg, {
        description: opts?.description,
        duration: opts?.duration ?? 6000,
        action: {
          label: opts?.undoLabel ?? "Desfazer",
          onClick: () => {
            void onUndo();
          },
        },
      }),
  }), []);
}
```

**Requisitos atendidos:**
- ✅ Assinatura pública do hook inalterada
- ✅ Nenhum consumidor precisa ser alterado
- ✅ 85 testes continuam verdes (sem quebra de contrato)

## 3. CORREÇÃO B — BUG DE WEEKDAY (dados, grave)

**Arquivo:** `src/components/study-plan/WeeklyGridEditor.tsx`

**Problema:** Inconsistência de `Weekday`.
- `types/study-plan.ts` define `Weekday = 0..6` com **0 = Domingo** (seguindo `Date.getDay()`)
- `ExceptionsManager.tsx` usa `["Dom","Seg","Ter","Qua","Qui","Sex","Sáb"]` (0=Domingo, correto)
- `WeeklyGridEditor.tsx` usava `["Seg","Ter","Qua","Qui","Sex","Sáb","Dom"]` (0=Segunda, errado) → blocos salvos na Rotina semanal caíam no dia da semana errado

**Solução:** Manter a EXIBIÇÃO visual em ordem Seg→Dom (UX), mas o valor persistido deve ser o `getDay()` correto (0=Domingo). Adicionados dois arrays de mapeamento:
- `DISPLAY_IDX_TO_WEEKDAY: [1,2,3,4,5,6,0]` — display index (0=Seg) → Weekday real (0=Dom)
- `WEEKDAY_TO_DISPLAY_IDX: [6,0,1,2,3,4,5]` — Weekday real (0=Dom) → display index (0=Seg)

**Pontos alterados:**
1. `getBlocksForCell` e `getBlockStartingAt`: aceitam `displayDayIdx` (0=Seg) e convertem internamente para Weekday real
2. `handleDrop`: converte `day` (display index) para Weekday real antes de salvar e antes de verificar colisão
3. Modal dropdown "Dia da semana": exibe ordem Seg→Dom mas `value` de cada option é o Weekday real
4. Modal botões "Dias da semana (múltipla seleção)": mesmo princípio — `onClick` passa Weekday real
5. Inicialização do form no modal: guarda o Weekday real vindo do bloco (não converte para display index)
6. Render da grade: chama `getBlockStartingAt(dayIdx, slotIndex)` com display index (sem cast incorreto)

**Diff (principais trechos):**
