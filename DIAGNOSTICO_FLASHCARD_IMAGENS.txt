================================================================================
D) Riscos ou dúvidas que encontrei
================================================================================

| Risco | Descrição |
|-------|-----------|
| Bucket `flashcard-images` não existe no Supabase | O serviço assume que existe; se não tiver sido criado no painel, upload falhará |
| Colunas no Supabase ausentes | Sem migração SQL, o push para `flashcards` vai falhar ou ignorar as colunas (conflito de schema) |
| `userId` hardcoded | Uploads vão para pasta `current-user/flashcards/...` no Storage — **não isola por usuário real**; precisa pegar `userId` do Clerk (`auth.userId`) |
| Conflito de shared cards | `addCard` cria cards para múltiplos usuários (`targetUserIds` loop) — a mesma imagem seria compartilhada (OK se URL pública), mas upload é feito **uma vez só** no modal; se falhar para um usuário, não há retry por usuário |
| Tamanho do bucket/Storage | 0.5 MB por imagem comprimida; sem política de limpeza de imagens órfãs (card deletado) |
| Estudo offline | Imagens são URLs públicas do Supabase Storage — **não funcionam offline** (precisa cache via Service Worker ou IndexedDB blob) |
| TypeScript errors existentes | 64 erros em 16 arquivos (maioria não relacionados a flashcards: Clerk v6 types, React refs, etc.) — não bloqueiam build, mas indicam dívida técnica |
